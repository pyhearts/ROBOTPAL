# ROBOTPAL

마이크의 한국어 발화를 전사하고, 선택적으로 카메라 이미지와 함께 발화를 분류해 대화 답변이나 이동·회전·정지의 상위 행동 계획을 출력합니다. 명시적인 실행 모드에서는 텍스트·음성의 시간 기준 명령을 가상 8족 장치에서 실행합니다. **실제 로봇 제어에는 연결되어 있지 않습니다.** 손 모양 인식은 독립 모드입니다.

## 설치

Python 3.12 환경에서 기본 기능 전체를 설치합니다. 화자 분리·등록은 별도 선택 설치입니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

필요한 기능만 설치할 수도 있습니다.

| 설치 파일 | 용도 |
|---|---|
| `requirements/core.txt` | 텍스트 분류·대화·행동 계획 |
| `requirements/speech.txt` | 직접 마이크·VAD·전사, core 포함 |
| `requirements/vision.txt` | 카메라·JPEG 처리 |
| `requirements/gesture.txt` | 손 모양 인식, vision 포함 |
| `requirements/legacy-speech.txt` | 선택적 화자 등록·식별·SepFormer, speech 포함 |

통합 모드는 speech와 vision이 필요합니다. 기본 전사는 Faster Whisper에 포함된 Silero ONNX 모델을 사용하며 PyTorch·SpeechBrain을 직접 불러오지 않습니다. 로컬 Whisper의 첫 실행에는 모델 다운로드가 필요합니다.

## 주요 실행법

```powershell
# 기본 실행: 음성·카메라로 AI 답변 또는 행동 계획 생성 — API 키 필요
.\.venv\Scripts\python.exe .\main.py

# 음성 전사만 실행 — 로컬 전사는 API 키 불필요
.\.venv\Scripts\python.exe .\main.py --transcribe-only

# 마이크 번호 확인과 입력 선택
.\.venv\Scripts\python.exe .\main.py --list-mics
.\.venv\Scripts\python.exe .\main.py --input-device 1

# 음성·카메라로 답변 또는 행동 계획 생성
.\.venv\Scripts\python.exe .\main.py --assist --input-device 1 --camera 0

# 텍스트 입력 — 카메라를 열지 않음
.\.venv\Scripts\python.exe .\main.py --plan --command "앞으로 30cm 이동해"
.\.venv\Scripts\python.exe .\main.py --plan

# 손 모양 인식 — API 키 불필요
.\.venv\Scripts\python.exe .\main.py --gesture --preview
.\.venv\Scripts\python.exe .\main.py --gesture --rule-set numbers --preview

# 전체 옵션
.\.venv\Scripts\python.exe .\main.py --help
```

옵션 없이 실행하면 `--assist`와 같은 AI 모드로 동작합니다. 최종 인식한 문장을 AI에 전달하고 `[AI 답변]`을 화면에 출력합니다. 카메라가 없어도 일반 대화와 정지는 처리합니다. API 키가 없으면 마이크를 열기 전에 설정 오류를 표시합니다. 전사만 필요하면 `--transcribe-only`를 사용하세요.

`ai_action_planner.py`도 같은 텍스트 처리 경로를 사용하는 대화형 진입점입니다. 답변을 소리로 읽어 주는 TTS는 코드 보관 상태이며 [복원 안내](archive/tts/RESTORE.md)를 참고하세요.

## API 설정과 처리 정책

AI 모드를 실행할 PowerShell 창에서 키를 설정합니다. `.env`를 자동으로 읽지는 않습니다.

```powershell
$env:OPENAI_API_KEY = "본인의_API_키"
# 선택: 분류 이후 대화·계획에 사용할 모델
$env:OPENAI_MODEL = "gpt-6-luna"
```

기본 모델과 분류 모델은 현재 코드에서 `gpt-6-luna`로 설정되어 있습니다. 분류는 `/decisions`, 대화·행동 계획은 `/responses`를 사용합니다. 서비스의 모델 접근 권한이 필요합니다.

| 분류 | 처리 |
|---|---|
| `concrete_command` | 방향·종료 조건이 명확한 이동·회전의 계획 생성 |
| `stop_command` | 추가 Responses 호출 없이 고정 정지 계획 출력 |
| `conversation` | 이미지 없이 독립적인 짧은 답변 |
| `visual_question` | 접수 당시 이미지로 답변, 영상이 없으면 고정 안내 |
| `not_command`, `needs_details`, `unsupported`, `uncertain` | 추가 Responses 호출 없이 고정 안내 |

확신도가 0.8 미만이면 불확실 안내를 출력합니다. 이 값은 초기 기준이며 실제 한국어 정확도를 보장하지 않습니다. 분류 실패 시 계획 API로 우회하지 않습니다. 대화에는 이전 문맥이나 도구를 전달하지 않습니다.

분류 제한 시간은 20초, 계획은 120초, 대화는 30초이며 자동 재시도는 없습니다. Responses에는 `store=False`를 지정하지만 서비스의 별도 보관 정책까지 비활성화하는 의미는 아닙니다.

최종 발화마다 분류 API 비용이 발생하며 대화·장면 질문·구체적 명령은 추가 API 비용이 발생할 수 있습니다. 기본 전사는 로컬에서 수행합니다. `--stt-backend openai`를 명시한 경우에만 발화 오디오를 전사 API로 전송하며 별도 비용이 발생합니다.

## 음성과 영상의 동작

직접 마이크 모드는 16 kHz 모노 입력을 Silero로 감지하고 로컬 Whisper small로 전사합니다. 기본 발화 종료 침묵은 0.45초입니다. 임시 인식은 표시만 하고 최종 품질 검사를 통과한 문장만 명령으로 전달합니다. 긴 발화는 조각으로 전사해도 최종 콜백은 한 번 전달하며, 한 조각이라도 품질 검사에 실패하면 전체를 보류합니다.

화자를 식별하거나 겹친 목소리를 분리하지 않습니다. 반복 발화도 별도 명령으로 받아 FIFO로 처리합니다. 최종 전사 접수 시점의 JPEG를 명령과 함께 고정하므로 API 처리 시점에 이미지가 바뀌지 않습니다. 프레임이 없거나 1초보다 오래됐으면 영상 없이 분류합니다.

영상이 없어도 일반 대화와 정지 계획을 처리합니다. 통합 모드의 구체적인 행동 요청과 장면 질문은 영상이 없으면 안내만 출력합니다. 텍스트 계획 모드의 구체적인 행동 요청은 영상 없이 처리할 수 있습니다.

기존 기본·계획 모드의 Ctrl+C에서는 입력을 중단하고 마지막 발화의 전사를 마친 뒤 카메라를 닫고 접수된 AI 명령을 순서대로 마무리합니다. API가 느리면 종료까지 시간이 걸릴 수 있습니다. 이 모드의 정지도 FIFO로 계획을 출력하며 하드웨어 긴급 정지 기능은 아닙니다. 가상 실행 모드의 정지·종료 정책은 아래 설명처럼 별도로 동작합니다.

음성 설정·진단·녹음·동일 음원 비교는 [SPEECH_GUIDE.md](docs/SPEECH_GUIDE.md)에 설명합니다.

## 로그와 코드 사용

실행마다 `logs/`에 `.log`와 `.jsonl`을 만듭니다. 한국 시간으로 화면 출력·전사·분류·API 사용량·오류를 기록하고 명령 ID로 결과를 연결합니다. 통합 모드는 명령별 JPEG를 `<실행 이름>_images/`에 저장합니다. 저장된 JPEG와 API에 전달할 JPEG는 같습니다. 일반 대화에 이미지를 보내지 않아도 접수 시 선택된 이미지는 저장됩니다.

원본 마이크 오디오와 연속 영상은 저장하지 않습니다. 평가용 WAV는 명시적으로 녹음을 선택할 때만 저장합니다. 로그에는 전사 내용과 이미지가 남으며 자동 삭제하지 않습니다. API 키는 텍스트 로그에서 가립니다.

```python
from module.decision_router import process_command, print_command_result
from module.session_log import capture_output

with capture_output():
    result = process_command("앞으로 30cm 이동해")
    print_command_result(result)
```

`CommandResult`, `CommandDecision`, `ActionPlan`과 `process_command`의 호출 방식은 유지합니다. 저수준 `create_action_plan`은 분류를 생략하므로 일반 진입점은 `process_command`를 사용하세요.

## 가상 8족 보행 실행

기본 실행과 `--plan`은 기존 동작을 유지합니다. `--execute`와 `--execute-voice`만 실행 관리자를 사용합니다. 이 기능은 **보행 순서와 명령 처리의 소프트웨어 모델**이며 물리 시뮬레이션·균형 검증·실제 이동이 아닙니다. 서보 각도, PWM, 발끝 좌표를 생성하지 않습니다. 추가 패키지나 실제 장치 없이 텍스트 가상 실행을 사용할 수 있습니다. 아래의 단순 시간 명령과 단독 정지는 API 없이 처리하고, 그 밖의 자연어 분류·계획에는 기존 API 키가 필요합니다. 음성 모드는 AI 처리 준비를 위해 시작 시 API 키를 확인합니다.

```powershell
# 텍스트 한 번 실행: 시간 조건을 명시
.\.venv\Scripts\python.exe .\main.py --execute --command "앞으로 2초 걸어"

# 계속 입력: 보행 중 새 명령으로 전환 가능
.\.venv\Scripts\python.exe .\main.py --execute
# 예: 앞으로 2초 → 왼쪽으로 1초 돌아 → 멈춰 → /quit

# 음성 최종 전사를 가상 실행으로 연결: 카메라는 열지 않음
.\.venv\Scripts\python.exe .\main.py --execute-voice --input-device 1

# API 없이 정지 경로만 확인
.\.venv\Scripts\python.exe .\main.py --execute --command "멈춰"
```

### 실행 가능한 계획과 제한

`ExecutablePlan`은 기존 `ActionPlan`의 `status`, `summary`, `steps`, `error`에 `actions`를 추가합니다. 설명과 실행 명령은 같은 구조화된 AI 응답에서 생성합니다. 설명 문자열을 다시 해석하지 않습니다. 기존 `process_command`, `ActionPlan`과 계획 전용 호출은 유지합니다.

```json
{
  "status": "plan",
  "summary": "가상 전진",
  "steps": ["앞으로 2초 이동한다.", "정지한다."],
  "error": "",
  "actions": [
    {"action": "forward", "duration_ms": 2000},
    {"action": "stop", "duration_ms": 0}
  ]
}
```

지원 동작은 `forward`, `backward`, `turn_left`, `turn_right`, `stop`입니다. 이동·회전은 1~10000ms(최대 10초)의 정수, 정지는 0ms입니다. 정지를 포함해 최대 10단계, 총 이동 시간은 20000ms 이하이며 마지막 단계는 정지여야 합니다. 하나라도 틀리면 전체를 거절합니다. 실행 직전에도 다시 검증합니다. invalid 계획은 빈 `summary`, `steps`, `actions`와 거절 이유인 `error`를 가집니다.

‘앞으로 10초 이동해’, ‘뒤로 2초 걸어줘’, ‘왼쪽으로 1초 돌아’, ‘오른쪽으로 3초 회전해줘’처럼 방향·숫자 시간·동작이 명확한 단일 명령은 전체 문장을 로컬 규칙으로 해석합니다. AI 분류의 확신도 변동으로 거절되지 않으며 마지막 정지를 자동으로 붙입니다. 부정문·질문·추가 절이 있는 문장은 부분만 추출하지 않고 기존 AI 경로로 처리합니다. 전체 AI 확신도 기준 0.8은 변경하지 않습니다. 명확한 시간 명령이 10초를 초과하면 시간을 줄이거나 나누지 않고 한도 안내와 함께 거절합니다.

시간은 ‘2초’, ‘0.5초’, ‘두 초’처럼 지정합니다. ‘앞으로 가’, ‘30cm’, ‘90도’, 횟수만 있는 명령은 실행하지 않습니다. 거리·각도·횟수를 시간으로 자동 환산하지 않으며, 이동을 나누어 제한을 우회하도록 요청하지 않습니다. 속도와 실제 보폭은 아직 정의되지 않았습니다.

### 다리와 보행 단계

좌우는 로봇 몸체 기준이고 번호는 앞에서 뒤로 1~4입니다.

| 그룹 | 다리 |
|---|---|
| A | R1, R3, L2, L4 |
| B | R2, R4, L1, L3 |

순서는 `전체 지지 → A 들기 → A 이동 → A 내리기 → 전체 지지 → B 들기 → B 이동 → B 내리기 → 전체 지지`입니다. 같은 그룹은 같은 단계에 있고, 반대 그룹은 지지 상태를 유지합니다. AI는 그룹이나 보행 순서를 변경하지 못합니다. 전진·후진·좌우회전은 같은 그룹 순서를 사용하고 발 이동 의도만 구분합니다.

가상 기본 시간은 전체 지지 100ms, 들기 150ms, 이동 200ms, 내리기 150ms입니다. `GaitTiming`으로 바꿀 수 있지만 항상 `simulation_only=True`이며 실제 하드웨어 보정값으로 인정하지 않습니다. 갱신이 지연되면 지나간 들기 동작을 한꺼번에 재생하지 않습니다.

정지는 다음 들기를 막고 현재 공중 그룹의 내리기와 전체 지지 전환을 진행합니다. 지정 이동 시간은 보행 시작부터 측정하며, 종료 후 내리기·지지 전환 시간이 추가될 수 있습니다. 출력의 ‘착지 동작 완료’는 타이머·상태 전환이 끝났다는 의미입니다. 발 접촉, 균형, 이동 거리의 확인이 아닙니다.

### 취소·전환·종료

실행 상태는 준비·실행 중·정지 중·고장입니다. 실행 입력 채널에서는 **새로운 비어 있지 않은 입력을 받으면 우선 기존 계획을 취소하고 정지**합니다. 새 입력이 대화나 잘못된 명령으로 분류되어도 이전 보행을 재개하지 않습니다. 새 유효 계획은 기존 동작의 정지 완료 후 시작합니다.

요청 세대 번호로 늦은 AI 응답을 폐기하고, 접수 후 10초가 지난 이동 요청은 시작하지 않습니다. 시작된 계획의 후속 단계는 계획 시간 제한 안에서 계속 진행합니다. 추론 작업자는 두 개로 제한하고 대기 입력은 가장 최근 하나만 유지합니다. 둘 다 느린 API를 기다리면 최신 요청도 만료될 수 있으며 이때 자동 재시도하지 않습니다.

최종 전사의 단독 ‘멈춰’, ‘정지’, ‘그만’은 API·일반 대기열을 우회합니다. ‘멈추지 마’, ‘멈춰?’와 혼합 문장은 이 단축 경로에 해당하지 않습니다. 임시 전사는 실행하지 않습니다. 음성 정지는 전사 지연이 있으므로 음성 모드에서는 Windows 콘솔의 **Space**로도 정지할 수 있습니다. 텍스트 모드에서는 정지 입력 후 Enter를 누릅니다.

Ctrl+C는 마지막 전사 마무리보다 먼저 정지를 요청하고 이후 전사 콜백을 차단합니다. 대기 계획을 폐기하고 가상 착지 전환을 기다린 뒤 종료합니다. 진행 중 API 응답을 기다리느라 종료를 막지 않으며, 그 응답은 실행에 반영하지 않습니다. `/quit`과 입력 종료도 현재 계획을 취소합니다.

### 가상 장치와 향후 USB 계약

`ExecutionManager`는 공통 `Device` 인터페이스를 사용합니다. `VirtualDevice`는 접수 지연, 중복 요청 거절, 오류 주입, 연결 단절, 재연결과 생존 신호 만료를 재현합니다. 제어기 자체가 동작 시간을 제한합니다. 고장은 유지되며 자동 재개하지 않습니다.

`SerialDevice`는 외부에서 주입한 비차단 바이트 전송 객체로 시험하는 줄 단위 JSON(NDJSON) 어댑터입니다. 현재는 포트를 여는 코드나 CLI 포트 옵션이 없고, `simulation=true`인 시험 상대만 허용합니다. `pyserial` 설치도 필요하지 않습니다. 실제 출력 장치는 거절합니다. 현재 Arduino 스케치는 이 프로토콜을 지원하지 않습니다.

향후 직렬 속도는 115200bps이며 모든 요청·응답은 `version=1`, `session`, `profile`, `request_id`를 포함합니다. `profile`은 프로필 식별값이며 가상 기본값은 `robotpal-virtual-v1`입니다. 실제 프로필에는 정규화한 설정의 SHA-256 식별값을 사용하도록 `HardwareProfile.fingerprint`를 제공합니다.

| 요청 op | 용도 |
|---|---|
| hello | 새 연결 세션·버전·프로필 확인 |
| ready | 구동 준비 확인; hello 접수 후 전송 |
| move | action, duration_ms를 담은 단일 이동·회전 |
| stop | 새 들기를 금지하고 정지 전환 요청 |
| status | 상태 조회 |
| heartbeat | 200ms 간격 생존 신호 |

응답의 `event`는 `accepted`, `completed`, `status`, `error`입니다. 시험 상대는 `simulation=true`도 포함해야 합니다. `move`와 `stop`은 접수 후 완료를 보고합니다. 접수 응답 제한은 500ms이고, 이동 완료 제한은 이동 시간+2초, 정지 완료 제한은 2초입니다. 부분 패킷은 버퍼링하고 잘못된 형식·ID·세션·프로필·응답 만료는 고장으로 처리합니다. 이동은 자동 재전송하지 않습니다. 통신 오류 시 가능한 경우 정지를 한 번 요청하지만 도달했다고 보장하지 않습니다.

생존 신호를 1초간 받지 못하면 가상 제어기는 새 발걸음을 막고 정지 절차를 시작합니다. 재연결은 새 세션으로 시작하고 이전 동작을 복원하지 않습니다. **이 동작을 실제 아두이노에서도 보장하려면 별도 펌웨어 구현·실물 시험이 필요합니다.**

하드웨어 프로필 검증기는 다리별 관절 역할·서보 모델·주소·채널·회전 방향·중립값·허용 범위·변화 속도와 보정·지지 검증·고장 정책을 요구합니다. 누락된 다리, 중복 채널·역할, 잘못된 범위를 거절합니다. 미완성·가상 프로필은 실제 구동 준비 검사에 통과하지 못합니다. 프로필 검사를 통과해도 이번 버전에는 실제 모터 구동 경로가 없습니다.

실행 이벤트는 기존 로그에 명령 ID와 연결해 계획·단계·취소·만료·고장·가상 여부를 기록합니다. 새 구현은 `executable_plan.py`, `gait.py`, `robot_device.py`, `execution.py`, `execution_runtime.py`로 나뉩니다.

## 실제 하드웨어 완성 후 해야 할 작업

다음은 아직 구현·검증되지 않았으며 소프트웨어 테스트 통과가 실제 보행 가능성을 의미하지 않습니다.

- [ ] **기구·배선:** 다리당 관절 수·역할, 링크 길이·관절 축, 서보 모델, 다리별 PCA9685 주소·채널, 회전 방향·중립값·허용 범위를 확정합니다. 예시 관절값을 실제 구동값으로 사용하지 않습니다.
- [ ] **발끝 경로:** 들기·이동·내리기와 지지 발 경로를 설계하고 역기구학 적용 여부를 결정합니다. 단순 관절 각도 보간에서 발이 바닥을 긁거나 미끄러지지 않는지 확인합니다.
- [ ] **A/B 지지:** A만 지지할 때와 B만 지지할 때 모두 무게중심·지지 영역·지지 여유를 확인합니다. 보행 전 구간의 충돌을 검사하고 필요한 몸체 이동과 전체 지지 시간을 보정합니다. 네 다리가 남았다는 사실만으로 안정성을 인정하지 않습니다.
- [ ] **실제 보행값:** 보폭·발 높이·단계 시간·속도·정지 경로를 실측합니다. 전진·후진·좌우회전을 각각 검증하고 확인된 방향만 활성화합니다.
- [ ] **전원·하중:** 실제 몸체 하중에서 토크 부족, 전압 강하, 기동·지지 전류, 발열과 배선을 확인하고 전원·보호 장치를 선정합니다. 서보 모델 확정 전 전원 용량을 임의로 정하지 않습니다.
- [ ] **정지·고장:** 일반 정지, 통신 단절, 관절 걸림·전원 고장을 구분합니다. 고장별 자세 유지·출력 해제 정책과 물리 정지 수단을 검증합니다. PCA9685 신호 중단을 전원 차단이나 기계적 제동으로 간주하지 않습니다.
- [ ] **센서:** 접촉 센서·IMU의 필요성과 모델은 미결정입니다. IMU만으로 발별 접촉을 확인할 수 없습니다. 센서 없는 보행은 보정된 평탄한 바닥 조건으로 제한합니다.
- [ ] **펌웨어:** 현재 `sketch_oct17a/sketch_oct17a.ino`는 부팅 시 PCA9685 두 대의 32채널에 중앙 신호를 출력합니다. 중앙값을 안전한 기립 자세로 간주하지 않습니다. 이 스케치는 이번 작업에서 수정·업로드하지 않습니다. 향후 부팅 중앙 정렬 제거, 실제 관절 출력·보행, 프로필 일치 검사, 독립 이동 시간 제한, 통신 만료 정지, 워치독, 재부팅 후 구동 금지를 적용합니다.
- [ ] **실제 USB 연결:** 실제 출력 활성화를 위한 별도 설계 검토 후 포트 연결을 추가하고 Mega의 재부팅·세션 초기화·버퍼·타이밍을 실측합니다. PC 생존 신호만으로 장치 전체 정상 동작을 판단하지 않습니다.
- [ ] **실물 시험:** 단일 관절 → 단일 다리 → 지지대 위 A/B 그룹 → 바닥 저속 보행 순으로 진행합니다. 기울기·미끄러짐·전압·발열·정지 시간의 허용값을 정하고 각 단계 통과 후 다음 단계로 넘어갑니다. 물리 정지와 모든 보행 단계의 통신 단절도 확인합니다.

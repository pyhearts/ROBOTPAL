# ROBOTPAL 변경 후 동작 순서도

화자 등록·식별과 SepFormer 분리는 기본 비활성화이며, 마이크 입력을 직접 전사하고 Decisions로 구체적 명령만 골라 행동 계획 API를 호출하고 모든 실행 출력을 로그에 기록합니다. 수정 전 상세 분석과 순서도는 `backups/before_api_20261018_105455/FLOWCHART.md`에 보존되어 있습니다.

## 1. 전체 실행

```mermaid
flowchart TD
    A([main.py 실행]) --> LOG[실행별 log 및 jsonl 기록 시작]
    LOG --> B[옵션 조합과 카메라 번호 검증]
    B --> C{실행 모드}
    C -->|기본| D[등록·분리 없이 마이크 한국어 전사]
    D --> E[음성 입력 라벨과 텍스트 출력]
    C -->|--assist| F[모든 화자의 음성과 카메라 영상으로 API 계획 생성]
    C -->|--plan| G[Decisions 분류 후 필요할 때 API 계획 생성]
    C -->|--gesture| H[손 모양 인식 및 결과 출력]
    F --> I[계획 또는 오류 출력]
    G --> I
```

`--enroll`은 명령행에서 제거했습니다. 기본 전사 모드와 손 모양 모드는 API 키가 필요하지 않습니다.

## 2. 직접 마이크 음성 처리

```mermaid
flowchart TD
    A[마이크 장치 및 전사 설정 확인] --> INIT[Silero와 로컬 Whisper 준비 또는 명시적 API 전사 선택]
    INIT --> B[16 kHz 모노 마이크 입력]
    B --> C[약 64ms 블록 복사 및 수집 시각 기록]
    C --> D[오디오 입력 큐]
    D --> MET[매초 음량·클리핑 로그]
    MET --> E[32ms 프레임으로 Silero 음성 확률 계산]
    E -.-> PRE[발화 중 최근 구간 임시 전사 - 최신 한 개만 유지]
    PRE --> SHOW[임시 인식 표시·로그 - 명령 전달 없음]
    E --> F{누적 오디오 20초 이상?}
    F -->|예| G[중간 전사 작업 추가]
    F -->|아니요| H{기본 0.45초 침묵?}
    G --> H
    H -->|아니요| B
    H -->|예| I{기본 최소 음성 0.12초 이상?}
    I -->|아니요| J[발화 상태 초기화]
    J --> B
    I -->|예| K[최종 전사 작업 추가 및 발화 상태 초기화]
    K --> B
    G -.-> L[별도 작업자가 선택한 모델로 한국어 전사 및 품질 검사]
    K -.-> L
    L --> M{최종 조각이며 합친 텍스트가 있는가?}
    M -->|아니요| L
    M -->|예| QUALITY{모든 조각이 품질 검사 통과?}
    QUALITY -->|아니요| RETRY[고정 재발화 안내 및 로그 - Decisions 호출 없음]
    QUALITY -->|예| N[음성 입력 라벨과 완성 텍스트를 한 번 콜백 전달]
    N --> L
    B -.-> STOP[Ctrl+C 시 입력 중단]
    STOP --> DRAIN[수집된 입력 및 끝나지 않은 발화 처리]
    DRAIN --> END[전사 큐 처리 후 작업자 종료]
```

기본 전사와 통합 모드는 SepFormer·ECAPA·화자 등록 파일을 사용하지 않습니다. 4초 분리 창, 채널 연결, 중첩 혼합, 분리 작업자와 분리 속도 측정이 실행되지 않습니다. 겹친 목소리는 분리하지 않고 하나의 마이크 입력으로 처리합니다. 출력은 `[음성 입력]`입니다. 기본 Silero 음성 확률 기준은 0.5이고, 시작 전 약 0.4초를 보존하며 짧은 명령을 위해 최소 음성을 0.12초로 조정했습니다. 로컬 최종 전사는 beam 3·한국어 지정·temperature 0·명령 용어 힌트를 사용합니다. 임시 전사는 beam 1이며 최종 작업을 우선합니다. 디코더에 반복 억제와 오디오 길이에 따른 출력 제한을 적용하고, 상한에 가까운 최종 결과는 보류합니다. 내부 VAD는 기본 비활성화합니다.

종료 시 마지막 오디오 수집 시각을 유지해 발화를 마무리합니다. Whisper 전사가 느리면 별도 전사 큐의 대기는 발생할 수 있습니다. 기존 분리 코드는 `run_separated_transcription`에 남아 있으며 기본 실행에서 호출하지 않습니다. 변경 직전 원본은 `backups/before_direct_mic_20261018_110826/`에 보존했습니다.

## 3. 모든 화자의 음성·영상 명령 접수

```mermaid
flowchart TD
    A([--assist]) --> B[OPENAI_API_KEY 및 모델 설정 확인]
    B --> C[카메라 및 AI 작업자 시작]
    C --> D[등록·음성 분리 없이 직접 마이크 전사 실행]
    C -.-> CAM[카메라 작업자가 최신 프레임 하나 유지]
    D --> E[전사 완료 콜백]
    E --> F{텍스트가 있는가?}
    F -->|아니요| END[해당 결과 무시]
    F -->|예| G[최신 프레임 복사]
    CAM -.-> G
    G --> H{카메라 정상·프레임 존재·나이 1초 이하?}
    H -->|아니요| OPT[사진 없이 텍스트 접수]
    OPT --> J
    H -->|예| I[JPEG 변환 및 명령 번호 부여]
    I --> J[텍스트와 JPEG를 FIFO 큐에 접수]
    J --> K[작업자가 접수 순서대로 텍스트를 Decisions로 분류]
    K --> TYPE{분류 결과}
    TYPE -->|일반 대화·정보 부족·미지원·불확실| FIX[고정 안내문 출력]
    TYPE -->|명확한 정지| STOPPLAN[고정 정지 계획 출력]
    TYPE -->|구체적인 행동 명령| IMG{접수 당시 영상이 있는가?}
    IMG -->|예| RESP[Responses로 행동 계획 생성 및 출력]
    IMG -->|아니요| NOIMG[영상 없음 고정 안내]
    FIX --> K
    STOPPLAN --> K
    RESP --> K
    NOIMG --> K
    D -.-> STOP[Ctrl+C 후 남은 음성 처리]
    STOP --> CLOSE[카메라 종료 및 신규 접수 중단]
    CLOSE --> DRAIN[접수된 AI 명령 완료 후 클라이언트 종료]
```

등록자·미등록자·`기타`를 구분하는 권한 필터가 없습니다. 영상이 없어도 텍스트 분류는 처리합니다. 분류 확신도 0.8 미만 또는 판단 거절은 고정 불확실 안내를 출력하고 계획을 만들지 않습니다. 분류 오류 역시 고정 안내를 출력하며 계획 API로 우회하지 않습니다. 각 명령은 전사 완료 시점에 복사한 JPEG를 유지합니다. 반복 명령도 각각 처리하며 선택한 JPEG 한 장은 실행별 logs/<실행 이름>_images/에 저장합니다. JSONL의 image_path와 command_id로 발화·결과와 연결합니다. 연속 영상은 저장하지 않습니다. AI 대기 큐에 크기 제한이 없어 요청이 많으면 종료까지 시간이 늘어날 수 있습니다.

## 4. 구체적 행동 요청의 OpenAI 계획 생성

```mermaid
flowchart TD
    A[명령 및 선택적 JPEG 바이트] --> B{명령이 비어 있는가?}
    B -->|예| INV[invalid 반환]
    B -->|아니요| C[API 클라이언트 준비 및 이미지 인자 검사]
    C --> D[텍스트와 JPEG data URL 구성]
    D --> E[행동 지침 및 엄격한 ActionPlan JSON 스키마 구성]
    E --> F[OpenAI Responses API 요청]
    F --> G{완료된 응답인가?}
    G -->|아니요| ERR[응답 오류]
    G -->|예| H{모델의 요청 거절인가?}
    H -->|예| INV
    H -->|아니요| I[JSON 및 상태별 필드 검증]
    I -->|유효| J[ActionPlan 반환]
    I -->|무효| ERR
    F -.->|인증·접속·시간 초과·한도 오류| ERR
```

기본 모델은 `gpt-5.4-mini`이며 `OPENAI_MODEL`로 변경합니다. 공식 엔드포인트를 사용하고 요청별 제한 시간은 120초, 자동 재시도는 0회, `store=False`입니다. 행동 계획 API에는 명령 텍스트와 선택적 JPEG만 보내며 원본 마이크 오디오·지문·스트림 이름은 보내지 않습니다. 별도로 `--stt-backend openai`를 선택한 경우에만 전사 API로 발화 오디오를 전송합니다.

`plan`은 비어 있지 않은 요약과 단계 및 빈 error를 요구합니다. `invalid`는 빈 요약·빈 단계와 거절 이유를 요구합니다. 구조 검증은 동작의 실제 실행 가능성을 독립적으로 확인하는 제어기가 아닙니다.

## 5. 손 모양 인식

```mermaid
flowchart TD
    A[카메라 및 MediaPipe 모델 준비] --> B[프레임 비동기 인식]
    B --> C{numbers 모드?}
    C -->|예| D[21개 관절로 OK와 숫자 우선 판정]
    C -->|아니요| E[기본 모델 허용 라벨 및 신뢰도 평가]
    D -->|규칙 성립| F[결과 안정화]
    D -->|불확실| E
    E --> F
    F --> G{같은 결과 400ms 유지 및 중복 아님?}
    G -->|예| H[이벤트 큐 및 콜백 출력]
    G -->|아니요| B
    H --> B
```

숫자 모드에서 규칙이 불확실하면 `Pointing_Up`, `Victory`, `Open_Palm`을 억제합니다. 인식 결과가 300ms 이상 사라지면 중복 방지 상태를 해제합니다. 손 모양은 AI 명령이나 Arduino 제어로 자동 연결되지 않습니다.

## 6. Arduino 독립 실행

```mermaid
flowchart TD
    A[Arduino 부팅] --> B[I2C 및 시리얼 초기화]
    B --> C[PCA9685 0x40 및 0x41 초기화 시도]
    C --> D[응답 없는 보드 오류 출력]
    D --> E[응답한 보드별 16채널에 1500µs 중앙 신호 설정]
    E --> F[빈 loop 반복 및 기존 PWM 유지]
```

PWM은 50Hz이며 채널 간 50ms 간격으로 설정합니다. Python과 Arduino 사이의 통신·보행 제어는 여전히 미구현입니다. 화자 등록 복원 방법과 실행 설정은 `README.md`를 참고하세요.

## 7. 출력 및 결과 기록

```mermaid
flowchart LR
    A[Python 표준 출력·오류] --> B[콘솔 표시]
    A --> C[실행별 UTF-8 log]
    D[입력·분류 답변·계획 응답·사용량·처리 시간] --> E[실행별 JSONL]
    C --> F[logs 폴더에 한국 시각으로 기록]
    E --> F
```

`module/session_log.py`가 실행별 기록을 담당하고 `module/decision_router.py`가 분류와 계획 분기를 담당합니다. API 키는 가리고 원본 오디오는 기록하지 않습니다. --assist에서 최종 전사 접수 시 선택한 이미지는 JPEG 파일로 저장하고 JSONL에는 상대 경로·명령 ID·해시를 기록합니다. 기존 버전은 `backups/before_decisions_20261018_113345/`에 보존했습니다.

## 8. 진단 및 설정 비교

`--list-mics`는 입력 장치를 나열하고, `--diagnose-mic`는 파일 저장 없이 음량을 진단합니다. `--record-sample`에 경로를 명시한 경우에만 평가용 WAV를 저장합니다. `--compare-stt`는 정답 목록의 같은 파일을 모델·beam 설정별로 처리하고 문자 오류율·핵심 조건 일치율·처리 시간 보고서를 `reports/`에 저장합니다. 사용법은 `SPEECH_GUIDE.md`를 참고하세요.

## 9. 임시 인식과 최종 작업의 우선순위

`module/live_transcription.py`는 최종·내부 조각 전사를 FIFO로 보존하고 임시 대기는 최신 한 개로 교체합니다. 최종 작업 처리 중에는 임시 요청을 받지 않습니다. 늦은 임시 출력은 숨기고 모든 명령 콜백은 최종·품질 확인 후 한 번만 호출합니다. 화면 상태와 임시 결과도 기존 로그에 기록합니다. 자세한 간격·출력 제한 설정은 `SPEECH_GUIDE.md`를 참고하세요.

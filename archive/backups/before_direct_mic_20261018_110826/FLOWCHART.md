# ROBOTPAL 변경 후 동작 순서도

화자 등록·식별은 기본 비활성화이며, 행동 계획은 OpenAI API로 생성합니다. 수정 전 상세 분석과 순서도는 `backups/before_api_20261018_105455/FLOWCHART.md`에 보존되어 있습니다.

## 1. 전체 실행

```mermaid
flowchart TD
    A([main.py 실행]) --> B[옵션 조합과 카메라 번호 검증]
    B --> C{실행 모드}
    C -->|기본| D[등록 없이 음성 분리 및 한국어 전사]
    D --> E[음성 스트림 번호와 텍스트 출력]
    C -->|--assist| F[모든 화자의 음성과 카메라 영상으로 API 계획 생성]
    C -->|--plan| G[텍스트 명령으로 API 계획 생성]
    C -->|--gesture| H[손 모양 인식 및 결과 출력]
    F --> I[계획 또는 오류 출력]
    G --> I
```

`--enroll`은 명령행에서 제거했습니다. 기본 전사 모드와 손 모양 모드는 API 키가 필요하지 않습니다.

## 2. 음성 처리

```mermaid
flowchart TD
    A[SepFormer와 Whisper small 준비] --> B[16 kHz 모노 마이크 입력]
    B --> C[오디오 입력 큐]
    C --> D[4초 창을 두 스트림으로 분리]
    D --> E[중첩 파형으로 채널 순서 연결]
    E --> F[누설 억제 및 1초 중첩 혼합]
    F --> G[3초씩 분리 결과 큐에 전달]
    G --> H[스트림별 RMS 음성·침묵 감지]
    H --> I{20초 누적?}
    I -->|예| J[중간 전사 조각을 큐에 추가]
    I -->|아니요| K{0.7초 침묵?}
    J --> K
    K -->|아니요| B
    K -->|예| L{유효 음성 0.25초 이상?}
    L -->|아니요| M[발화 상태 초기화]
    M --> B
    L -->|예| N[최종 전사 조각 추가 및 발화 상태 초기화]
    N --> B
    J -.-> O[전사 작업자가 Whisper로 한국어 전사]
    N -.-> O
    O --> P{최종 조각이며 합친 텍스트가 있는가?}
    P -->|아니요| O
    P -->|예| Q[음성 스트림 번호와 완성 텍스트를 콜백으로 전달]
    Q --> O
```

기본 경로는 화자 등록 파일을 읽지 않고 ECAPA 지문 모델도 로드하지 않습니다. 스트림 번호는 고정된 사람의 신원이 아닙니다. 분리 창은 최대 두 번 시도하고 실패하면 해당 이동 구간을 무음으로 전달합니다. Ctrl+C 시 남은 큐와 발화를 마무리합니다.

## 3. 모든 화자의 음성·영상 명령 접수

```mermaid
flowchart TD
    A([--assist]) --> B[OPENAI_API_KEY 및 모델 설정 확인]
    B --> C[카메라 및 AI 작업자 시작]
    C --> D[화자 등록 없이 실시간 전사 실행]
    C -.-> CAM[카메라 작업자가 최신 프레임 하나 유지]
    D --> E[전사 완료 콜백]
    E --> F{텍스트가 있는가?}
    F -->|아니요| END[해당 결과 무시]
    F -->|예| G[최신 프레임 복사]
    CAM -.-> G
    G --> H{카메라 정상·프레임 존재·나이 1초 이하?}
    H -->|아니요| ERR[해당 명령 오류 출력]
    H -->|예| I[JPEG 변환 및 명령 번호 부여]
    I --> J[텍스트와 JPEG를 FIFO 큐에 접수]
    J --> K[AI 작업자가 접수 순서대로 API 호출]
    K --> L[계획 또는 오류 출력]
    L --> K
    D -.-> STOP[Ctrl+C 후 남은 음성 처리]
    STOP --> CLOSE[카메라 종료 및 신규 접수 중단]
    CLOSE --> DRAIN[접수된 AI 명령 완료 후 클라이언트 종료]
```

등록자·미등록자·`기타`를 구분하는 권한 필터가 없습니다. 각 명령은 전사 완료 시점에 복사한 JPEG를 유지합니다. 반복 명령도 각각 처리하며 영상 파일을 저장하지 않습니다. AI 대기 큐에 크기 제한이 없어 요청이 많으면 종료까지 시간이 늘어날 수 있습니다.

## 4. OpenAI 행동 계획 생성

```mermaid
flowchart TD
    A[명령 및 선택적 JPEG 바이트] --> B{명령이 비어 있는가?}
    B -->|예| INV[invalid 반환]
    B -->|아니요| C[API 클라이언트 준비 및 이미지 인자 검사]
    C --> D[텍스트와 JPEG data URL 구성]
    D --> E[행동 지침 및 엄격한 ActionPlan JSON 스키마 구성]
    E --> F[OpenAI Responses API 요청]
    F --> G{완료된 응답인가?}
    G -->|아니요| ERR[응답 오류]
    G -->|예| H{모델의 요청 거절인가?}
    H -->|예| INV
    H -->|아니요| I[JSON 및 상태별 필드 검증]
    I -->|유효| J[ActionPlan 반환]
    I -->|무효| ERR
    F -.->|인증·접속·시간 초과·한도 오류| ERR
```

기본 모델은 `gpt-5.4-mini`이며 `OPENAI_MODEL`로 변경합니다. 공식 엔드포인트를 사용하고 요청별 제한 시간은 120초, 자동 재시도는 0회, `store=False`입니다. API에는 명령 텍스트와 선택적 JPEG만 보내며 원본 마이크 오디오·지문·스트림 이름은 보내지 않습니다.

`plan`은 비어 있지 않은 요약과 단계 및 빈 error를 요구합니다. `invalid`는 빈 요약·빈 단계와 거절 이유를 요구합니다. 구조 검증은 동작의 실제 실행 가능성을 독립적으로 확인하는 제어기가 아닙니다.

## 5. 손 모양 인식

```mermaid
flowchart TD
    A[카메라 및 MediaPipe 모델 준비] --> B[프레임 비동기 인식]
    B --> C{numbers 모드?}
    C -->|예| D[21개 관절로 OK와 숫자 우선 판정]
    C -->|아니요| E[기본 모델 허용 라벨 및 신뢰도 평가]
    D -->|규칙 성립| F[결과 안정화]
    D -->|불확실| E
    E --> F
    F --> G{같은 결과 400ms 유지 및 중복 아님?}
    G -->|예| H[이벤트 큐 및 콜백 출력]
    G -->|아니요| B
    H --> B
```

숫자 모드에서 규칙이 불확실하면 `Pointing_Up`, `Victory`, `Open_Palm`을 억제합니다. 인식 결과가 300ms 이상 사라지면 중복 방지 상태를 해제합니다. 손 모양은 AI 명령이나 Arduino 제어로 자동 연결되지 않습니다.

## 6. Arduino 독립 실행

```mermaid
flowchart TD
    A[Arduino 부팅] --> B[I2C 및 시리얼 초기화]
    B --> C[PCA9685 0x40 및 0x41 초기화 시도]
    C --> D[응답 없는 보드 오류 출력]
    D --> E[응답한 보드별 16채널에 1500µs 중앙 신호 설정]
    E --> F[빈 loop 반복 및 기존 PWM 유지]
```

PWM은 50Hz이며 채널 간 50ms 간격으로 설정합니다. Python과 Arduino 사이의 통신·보행 제어는 여전히 미구현입니다. 화자 등록 복원 방법과 실행 설정은 `README.md`를 참고하세요.
